# Code Review 机制

每个开发阶段结束后，必须通过 **Review Gate**（质量门禁）才能进入下一阶段。

---

## 原则

1. **实现者不审自己的代码** — 每个 gate 由独立子代理或人工审阅
2. **门禁脚本是第一道防线** — 自动化检查，快速反馈
3. **关键阶段需人工确认** — 架构设计、安全敏感、用户体验
4. **修复后重审** — 门禁失败必须修复并重跑，不允许带问题合并

---

## Gate 流程

### 自动化检查（每次必跑）

```bash
./scripts/review.sh            # 全量检查
./scripts/review.sh --quick    # 跳过慢速检查（3.9 兼容性）
```

**检查项**：
- ✅ 代码格式（black + isort）
- ✅ 单元测试（离线测试全通过）
- ✅ 导入健全性（核心模块不依赖可选依赖）
- ✅ Python 3.9 兼容性（真实 3.9 环境验证）
- ✅ 安全扫描（硬编码凭据、危险调用）
- ✅ 文档一致性（版本号、依赖列表）
- ✅ ESP-IDF 固件规范（CMakeLists.txt、无硬编码凭据）

**退出码**：
- `0` — 通过，可继续
- `1` — 失败，必须修复

---

### 子代理评审（关键阶段）

**适用场景**：
- 新增 API 接口（服务端）
- 新增组件或模块（ESP 固件）
- 架构调整（目录结构、依赖关系）
- 安全敏感代码（加密、认证、配网）

**评审要点**（见 `requesting-code-review` skill）：
1. **安全** — 无硬编码凭据、无 SQL 注入、输入验证
2. **可读性** — 命名清晰、注释充分、避免魔法数字
3. **可维护性** — 职责单一、低耦合、易测试
4. **性能** — 无明显瓶颈、内存泄漏、阻塞调用
5. **兼容性** — Python 3.9+、ESP-IDF 5.1+

**操作**：
```python
# 调用子代理评审
delegate_task(
    goal="审阅 bus_arrival_board/server.py",
    context="""
本次新增服务端 API /api/epd/frame.bin，用于向 ESP32 提供墨水屏帧数据。
审阅要点：
- ETag 缓存实现是否正确（SHA256 计算、If-None-Match 头处理）
- 错误处理是否充分（查询失败、渲染失败、网络中断）
- 性能是否可接受（渲染耗时、内存占用）
- 安全问题（是否暴露敏感信息、是否有 DoS 风险）
    """,
    role="leaf"
)
```

---

### 人工确认（你参与）

**必需人工确认的决策**：
- 硬件选型（ESP32-S3 vs ESP32-C3）
- 功耗目标（续航要求影响深度睡眠间隔）
- 用户体验（配网流程、故障提示）
- 优先级调整（P0/P1/P2 范围变化）

**流程**：
1. 我提供技术方案与权衡分析
2. 你确认决策或提出调整
3. 我根据反馈修改并重审

## Review Gate 清单

| Gate | 阶段 | 自动化 | 子代理审 | 人工确认 |
|------|------|--------|----------|----------|
| **Gate 0** | Review 机制建立 | ✅ scripts/review.sh | - | 你批准本文档 |
| **Gate 1** | 服务端 API | ✅ lint/test | ✅ 接口设计/ETag/安全 | - |
| **Gate 2** | ESP-IDF 脚手架 | ✅ CMake 语法 | ✅ 结构/组件化 | 你确认目录布局 |
| **Gate 3** | epd_driver 组件 | ✅ 编译通过 | ✅ SPI 时序/驱动逻辑 | - |
| **Gate 4** | 网络与电源组件 | ✅ 编译通过 | ✅ WiFi 安全/功耗优化 | 你确认配网方式 |
| **Gate 5** | 主程序集成 | ✅ 全量测试 | ✅ 流程完整性 | 你真机验证 |
| **Gate 终审** | 推送前 | ✅ CI 绿 | ✅ 文档完整性 | 你最终批准 |

## 修复流程

**当门禁失败时**：

1. **查看失败项**：
   ```bash
   ./scripts/review.sh  # 看哪一项 ❌
   ```

2. **修复问题**：
   - 格式：`black . && isort .`
   - 测试：`pytest` 查看具体失败用例
   - 导入：检查是否误把可选依赖写进核心模块
   - 安全：移除硬编码凭据，改用环境变量或配置文件

3. **重跑门禁**：
   ```bash
   ./scripts/review.sh  # 必须全绿才能继续
   ```

4. **子代理重审**（若需要）：
   修复后重新派遣子代理，确认问题已解决

---

## 典型问题与快速修复

| 问题 | 快速修复 |
|------|----------|
| `black 未格式化` | `black .` |
| `isort 顺序错误` | `isort .` |
| `测试失败` | `pytest -v` 查看具体失败，修复后重跑 |
| `3.9 导入失败` | 检查 `int \| None` 需 `from __future__ import annotations` |
| `硬编码凭据` | 移到 `.env` 或 `config.yaml`，用 `os.getenv()` 读取 |
| `版本号不一致` | 三处同步：`__init__.py` / `pyproject.toml` / `setup.py` |
| `CMakeLists.txt 缺失` | 每个组件目录必须有，参考现有组件模板 |

## 示例：Gate 1 完整流程

### 1. 我完成服务端代码
```bash
# 新增 bus_arrival_board/server.py
# 新增 tests/test_server_api.py
# 更新 pyproject.toml [server] 可选依赖
```

### 2. 我跑自动化门禁
```bash
./scripts/review.sh --quick
# ✅ 通过 7  失败 0  跳过 3
# ✅ 门禁通过
```

### 3. 我派子代理审阅
```python
delegate_task(
    goal="审阅 bus_arrival_board/server.py 安全性与设计",
    context="...",  # 贴上代码 + 设计意图
    role="leaf"
)
```

### 4. 子代理给出反馈
- ✅ ETag 实现正确
- ⚠️  建议增加速率限制（防 DoS）
- ⚠️  错误响应缺少详细信息

### 5. 我根据反馈修复
```python
# 增加 slowapi 速率限制
# 错误响应增加 {"error": "...", "detail": "..."}
```

### 6. 重跑门禁 + 重审
```bash
./scripts/review.sh --quick  # 再次通过
# 重新派子代理确认修复
```

### 7. 我提交并报告
```bash
git add -A
git commit -m "feat(server): /api/epd/frame.bin endpoint + ETag cache"
# 告诉你：Gate 1 通过，可进 Gate 2
```

### 8. 你确认或提意见
- 你说"继续" → 我开始 Phase 2
- 你说"加个日志" → 我改完重过 Gate 1

## 退出标准

**每个 Gate 必须满足**：
- ✅ `./scripts/review.sh` 全绿
- ✅ 子代理审阅通过（若需要）
- ✅ 你的确认（若需要）

**最终推送前**：
- ✅ 所有 Gate 通过
- ✅ CI 编译成功（GitHub Actions）
- ✅ 文档完整可复现
- ✅ 你真机验证（有硬件时）
