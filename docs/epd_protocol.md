# EPD-nRF5 BLE 协议参考

本文档记录 [tsl0922/EPD-nRF5](https://github.com/tsl0922/EPD-nRF5) 固件的蓝牙协议，
供 `bus_arrival_board.epd` 模块实现参考。

**协议来源：** 该项目的上位机是开源的 Web Bluetooth 网页，协议直接可从
`html/js/main.js` 读出，无需抓包逆向。本文档中的 UUID、命令码、分包策略
均来自该源码文件。

> 本仓库的 Python 实现是独立编写的，未复制原项目代码。原项目采用 GPL-3.0。

---

## GATT 结构

设备广播名称形如 `NRF_EPD_XXXX`，后四位取自蓝牙 MAC 地址。

| 角色 | UUID |
|------|------|
| Service | `62750001-d828-918d-fb46-b6c11c675aec` |
| 命令特征（write + notify） | `62750002-d828-918d-fb46-b6c11c675aec` |
| 版本特征（read） | `62750003-d828-918d-fb46-b6c11c675aec` |

注意上位机用的是 `acceptAllDevices: true` 配合 `optionalServices`，
说明它不依赖名称过滤。用 Python 扫描时，按名称前缀或 Service UUID 匹配都可行。

---

## 报文格式

极简设计：**首字节是命令码，其后是数据载荷**。

```
+--------+------------------+
| cmd(1) | payload(0..N)    |
+--------+------------------+
```

对应上位机的 `write(cmd, data)` 函数。

---

## 命令码表

| 命令 | 值 | 载荷 | 说明 |
|------|-----|------|------|
| `SET_PINS` | `0x00` | 引脚配置 hex 串 | 如 `0508090A0B0C0D` |
| `INIT` | `0x01` | 驱动型号 | 初始化屏幕驱动 |
| `CLEAR` | `0x02` | 无 | 清屏 |
| `SEND_CMD` | `0x03` | 控制器命令 | 透传给屏控制器 |
| `SEND_DATA` | `0x04` | 数据 | 透传数据 |
| `REFRESH` | `0x05` | 无 | 刷新上屏 |
| `SLEEP` | `0x06` | 无 | 屏幕休眠 |
| `SET_TIME` | `0x20` | 时间数据 | 对时（日历模式用） |
| `WRITE_IMG` | `0x30` | 图像分包 | 写图像，**需固件 v1.6+** |
| `SET_CONFIG` | `0x90` | 配置 | 写入配置 |
| `SYS_RESET` | `0x91` | 无 | 系统复位 |
| `SYS_SLEEP` | `0x92` | 无 | 系统休眠 |
| `CFG_ERASE` | `0x99` | 无 | 擦除配置 |

---

## 典型时序

首次连接（需要配置驱动）：

```
SET_PINS(引脚配置)
  → INIT(驱动型号)
  → WRITE_IMG(分包 × N)
  → REFRESH
```

已配置过的设备，可以省略 `SET_PINS`：

```
INIT → WRITE_IMG(× N) → REFRESH
```

## 图像传输的两个关键细节

这两点是移植时最容易翻车的地方。

### 1. 分包大小 = MTU − 2

```
chunk_size = mtu_size - 2
```

减 2 是因为首字节命令码 + 帧头占位。**不要用固定 20 字节**，
应读取协商后的实际 MTU（nRF52 通常能协商到较大值，传图明显更快）。

### 2. 交错 ACK 策略

上位机不是全部用带响应写，也不是全部不带：

- 每 `interleaved_count`（默认 20）个包用一次**带响应写**
- 其余用**不带响应写**

原因是权衡：全部带响应会很慢（每包都要等 ACK），
全部不带响应容易丢包。交错是折中方案。

### 3. RLE 压缩（可选）

固件支持时（由版本决定），上位机会尝试 RLE 压缩，
但**仅当压缩后确实更小才启用**：

```javascript
const useRle = rleSupport && rleLength < data.length;
```

首版实现可以跳过 RLE，直接发原始位图。

## 屏幕分辨率参考

墨水屏按尺寸对应固定分辨率，渲染时必须匹配：

| 尺寸 | 分辨率 | 常见驱动 |
|------|--------|----------|
| 1.54" | 152×152 / 200×200 | — |
| 2.13" | 104×212 / 122×250 | — |
| 2.9" | 128×296 / 168×384 | — |
| 4.2" | **400×300** | UC8176 / SSD1619 / JD79668 |
| 5.83" | 600×448 / 648×480 | UC8159 / UC8179 |
| 7.5" | **800×480** / 640×384 / 880×528 | UC8179 / SSD1677 |

单色位图字节数 = `width × height / 8`。
例如 4.2 寸黑白：`400 × 300 / 8 = 15000` 字节。

## 已知限制

- **只有 v1.6+ 固件支持 `WRITE_IMG`**，更早版本需要用 `SEND_CMD`/`SEND_DATA` 透传
- v1.7 以下固件上电无反应是正常的，需上位机主动操作
- 驱动型号选错会导致屏幕无反应，官方网页底部有「开发模式」可逐个试
