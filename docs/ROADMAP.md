### 1.3 电池电压监测
**为什么必做**: 电池设备不知道自己快没电，设计有缺陷

**方案**: ESP32-S3 内置 ADC，分压电阻读 LiPo 电压
```c
// power_mgmt.c 新增
float power_get_battery_voltage(void);  // 读 ADC1 通道
bool power_is_battery_low(void);        // < 3.4V 告警
```

**行动**:
- [ ] ADC 读电压（GPIO 映射 ADC1_CHANNEL_X）
- [ ] 低电压时发警告到服务端（HTTP header: X-Battery-Low: 1）
- [ ] 服务端渲染低电量图标

## Phase 2: 硬件首次验证（前置依赖，无法跳过）

**状态**: 代码从未在真硬件运行过  
**风险**: UC8176 驱动、SPI 时序、位图极性全是纸面推理

**采购清单**:
- ESP32-S3 开发板（推荐 ESP32-S3-DevKitC-1）
- UC8176 4.2" 黑白墨水屏（微雪或 GDEW042T2）
- 杜邦线若干
- （可选）逻辑分析仪（抓 SPI 波形调试）

**验证步骤**:
1. 按 `firmware/README.md` 接线（SPI + DC/RST/BUSY/CS）
2. 烧录: `idf.py -p /dev/ttyUSB0 flash monitor`
3. 首次上电 SmartConfig 配网（微信扫码）
4. 观察串口日志 + 屏幕刷新

**预期问题与应对**:
| 现象 | 可能原因 | 修法 |
|------|---------|-----|
| 屏幕空白 | 位图极性反（0/1 代表黑白反了） | epd_driver.c 翻转数据 |
| 雪花/乱码 | SPI 时序不对 | 降时钟到 2MHz 重试 |
| BUSY 超时 | 引脚接错或屏幕坏 | 万用表测 BUSY 电平 |
| 刷新黑屏 | 电源不足（墨水屏瞬时 200mA+） | 换 USB 口或加电容 |

**行动**:
- [ ] 采购硬件（预算 ~200 元）
- [ ] 接线烧录
- [ ] 调通第一帧
- [ ] 记录实测参数（时序、极性）到 epd_uc8176.h

## Phase 3: 服务端扩展（零固件成本的红利区）

这些全在 Python 侧做，固件一行不动。

### 3.1 多站点轮播
**场景**: 同时关心"安翼嘉寓"和"清华东路"两个站  
**实现**: 服务端每次渲染随机一个，或轮询

### 3.2 天气/日历混排
**场景**: 公交下面显示今天天气和待办  
**实现**: Pillow 多区域拼贴，数据源 OpenWeather + Google Calendar

### 3.3 局部刷新
**收益**: 4 秒全刷变 0.5 秒，残影更轻  
**挑战**: UC8176 支持局部刷新，但需要 LUT 波形参数调优（硬件相关）

## Phase 4: 交互与体验增强

### 4.1 按钮唤醒
**场景**: 想看就按一下，不等 5 分钟定时  
**方案**: RTC GPIO 中断唤醒
```c
esp_sleep_enable_ext0_wakeup(GPIO_NUM_X, 0);  // 按钮按下低电平触发
```

### 4.2 三色屏红色标注
**场景**: 即将到站的车用红色高亮  
**前提**: 换三色屏硬件（当前是黑白）

### 4.3 ULP 协处理器定时
**收益**: 主核全关，功耗从 20µA 降到 < 5µA  
**难度**: ULP 汇编编程，调试困难

## 不做的事（明确边界）

- ❌ **屏上交互菜单** — 4 秒刷新的墨水屏做交互体验必然糟糕
- ❌ **固件塞中文字库** — 2MB+ 字库换来的是失去"改布局不刷固件"优势
- ❌ **蓝牙配网** — SmartConfig 已够用，加蓝牙只增加 IRAM 负担
