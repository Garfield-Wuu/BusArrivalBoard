# 硬件选型与部署指南

## 概述

本文档提供 BusArrivalBoard 项目的硬件选型建议、接线指南、供电方案和界面布局设计。

**核心需求：**
- ESP32 系列芯片（Wi-Fi + 足够内存）
- 4.2-4.7 寸墨水屏（可视距离 2-3 米）
- 低功耗设计（电池续航 7-30 天）
- 稳定的 3.3V 供电

---

| 屏幕尺寸 | 分辨率 | 可视距离 | 适用场景 |
|---------|--------|---------|---------|
| 2.9" | 296×128 | 0.5-1 米 | 桌面个人使用 |
| **4.2"** | 400×300 | **1-2 米** | **家庭/办公桌** ✅ |
| **4.7"** | 540×960 | **2-3 米** | **墙面挂载** ✅ |
| 7.5" | 800×480 | 3-5 米 | 公共区域显示 |

**推荐：** 4.2"-4.7" 为公交到站显示的最佳尺寸，字体可达 24-36pt 保证可读性。

---

### 刷新模式与速度

#### 黑白屏 vs 三色屏

| 类型 | 刷新速度 | 残影 | 功耗 | 推荐度 |
|------|---------|------|------|--------|
| **黑白（B/W）** | **2-5 秒（全刷）** | 可通过定期全刷清除 | 低 | ⭐⭐⭐⭐⭐ |
| 三色（B/W/R） | 15-30 秒 | 更明显 | 中等 | ⭐⭐（刷新太慢） |

**结论：** 公交到站显示需要频繁更新（60 秒间隔），**强烈推荐黑白屏**，三色屏刷新时间过长且无实际优势。

---

#### 刷新类型详解

**1. 全刷新（Full Refresh）**
- **过程：** 黑 → 白 → 黑 → 白 → 目标图像（多次反转清除残影）
- **时间：** 2-5 秒（与屏幕尺寸相关）
- **功耗：** 相对较高（完整电压序列）
- **残影：** 完全清除
- **使用时机：** 首次显示、每 10-20 次局刷后清理

**2. 局部刷新（Partial Refresh）**
- **过程：** 仅更新变化区域，跳过清屏步骤
- **时间：** 0.5-1 秒
- **功耗：** 低（仅刷新局部）
- **残影：** 轻微累积，需定期全刷清除
- **使用时机：** ETA 数字更新、拥挤度图标变化

**3. 快速刷新（Fast Mode）**
- **支持：** 部分新型号（如 GoodDisplay GDEY042T81）
- **时间：** < 1 秒
- **残影：** 明显，不适合长期使用
- **使用时机：** 特殊场景（动画演示），不推荐用于本项目

**推荐策略：**
```
循环 1-9：  局部刷新 ETA 区域
循环 10：   全刷整屏（清除残影）
循环 11-19：局部刷新
循环 20：   全刷整屏
...
```

---

### 温度与环境适应性

**工作温度范围：** 0-50°C（厂商规格，实际可能更宽）

**温度影响：**
- **低温（< 10°C）：** 刷新速度变慢（可能 10-15 秒），残影增加
- **高温（> 40°C）：** 刷新加快，但长期暴露可能损伤屏幕

**应对措施：**
- 室内使用无需特殊处理
- 室外部署建议加装保护罩，避免阳光直射
- 冬季室外可能需要加热片（需额外功耗）

**寿命：** 墨水屏无背光，理论寿命 > 10 万次刷新（按每分钟刷新计算约 2-3 年连续使用）

## 供电与续航

### 功耗分析

#### 工作模式电流实测（估算值，实际需用万用表测量）

| 模式 | ESP32 | ESP32-S3 | 说明 |
|------|-------|----------|------|
| Deep Sleep | 10-150 μA | 7-240 μA | 型号差异大，需实测 |
| Wi-Fi 连接 | 80-160 mA | 80-120 mA | 持续 5-15 秒 |
| HTTPS 请求 | 100-180 mA | 90-150 mA | 持续 3-10 秒 |
| 墨水屏全刷 | 30-50 mA | 30-50 mA | 持续 2-5 秒 |
| 墨水屏局刷 | 20-35 mA | 20-35 mA | 持续 0.5-1 秒 |

**注意：** 以上为估算值，实际功耗受网络信号强度、代码优化、外设配置影响较大。

---

### 续航时间计算

**公式：**
```
续航时间（小时） = 电池容量（mAh） / 平均电流（mA） × 放电效率（0.8）
```

**单次唤醒周期功耗模型（60 秒刷新间隔）：**

| 阶段 | 时长（秒） | 电流（mA） | 电荷（mAh） |
|------|-----------|-----------|------------|
| Deep Sleep | 45 | 0.05 | 0.000625 |
| Wi-Fi 连接 | 8 | 120 | 0.267 |
| HTTPS 请求 | 4 | 150 | 0.167 |
| 墨水屏局刷 | 1 | 30 | 0.008 |
| Deep Sleep 切换 | 2 | 50 | 0.028 |
| **总计** | **60** | - | **0.47** |

**平均电流：** 0.47 mAh/分钟 × 60 = **28.2 mA**

---

### 续航估算示例

#### 配置 A：18650 锂电池（2500 mAh）

```
续航 = 2500 mAh / 28.2 mA × 0.8 = 71 小时 ≈ 3 天
```

#### 配置 B：10000 mAh 移动电源

```
续航 = 10000 mAh / 28.2 mA × 0.8 = 284 小时 ≈ 12 天
```

#### 配置 C：优化低功耗（Deep Sleep < 10 μA，夜间停止刷新）

**日间（6:00-23:00，17 小时）：** 60 秒刷新
- 每小时消耗：28.2 mA × 17 = 480 mAh/天（日间）

**夜间（23:00-6:00，7 小时）：** 深度睡眠
- 每小时消耗：0.01 mA × 7 = 0.07 mAh/天（夜间）

**总计：** 480 + 0.07 ≈ **480 mAh/天**

```
续航（2500 mAh 电池） = 2500 / 480 = 5.2 天
续航（10000 mAh 电源）= 10000 / 480 = 20.8 天
```

**重要提醒：** 以上为理论计算，实际续航受以下因素影响：
- Wi-Fi 信号强度（弱信号导致连接时间延长）
- 网络延迟（HTTPS 请求耗时）
- 环境温度（低温电池容量下降）
- 电池老化程度

**建议：** 首次部署时用万用表实测 24 小时平均电流，再精确计算续航。

---

### 推荐供电方案

#### 方案 1：USB 持续供电（推荐）

**适用：** 室内固定位置，有 USB 插座

**适用：** 临时部署、移动场景
- **电池：** 18650 锂电池（2500-3500 mAh）

- **成本：** 电池 ¥10 + 充电模块 ¥3

#### 方案 3：大容量移动电源

**适用：** 户外展示、临时活动
- **电源：** 10000 mAh 移动电源

- **优势：** 即买即用，无需焊接
- **劣势：** 体积大，不适合嵌入式安装

---

#### 方案 4：太阳能供电（高级）

**适用：** 户外长期部署
- **组件：** 6V 太阳能板（2W）+ 18650 电池 + CN3791 充电管理
- **续航：** 理论无限（阴雨天需电池支撑）
- **成本：** ¥50-100

## 接线指南（方案 B：微雪 4.2" + ESP32）

### SPI 引脚对照表

**微雪 4.2" 墨水屏引脚定义：**

| 屏幕引脚 | 功能 | ESP32 GPIO | 说明 |
|---------|------|-----------|------|
| VCC | 3.3V 电源 | 3V3 | **不能接 5V！** |
| GND | 地 | GND | 公共地 |
| DIN | SPI MOSI | GPIO 23 | 主机输出从机输入 |
| CLK | SPI SCK | GPIO 18 | 时钟信号 |
| CS | 片选 | GPIO 5 | 低电平有效 |
| DC | 数据/命令 | GPIO 17 | 高=数据，低=命令 |
| RST | 复位 | GPIO 16 | 低电平复位 |
| BUSY | 忙信号 | GPIO 4 | 高=屏幕忙，禁止操作 |

**ESP32 默认 SPI 引脚（VSPI）：**
- MOSI: GPIO 23
- MISO: GPIO 19（墨水屏无需，仅单向传输）
- SCK: GPIO 18
- CS: 可自定义（推荐 GPIO 5）

---

### 接线步骤

#### 1. 准备材料
- 杜邦线（母对母）× 8 根
- 面包板（可选，便于临时测试）
- ESP32 开发板（确认引脚丝印）
- 微雪墨水屏模块

---

#### 2. 接线图（文字描述）

```
墨水屏侧          ESP32 侧
┌─────┐          ┌─────────┐
│ VCC ├─────────>│ 3V3     │  ← 红线
│ GND ├─────────>│ GND     │  ← 黑线
│ DIN ├─────────>│ GPIO 23 │  ← 蓝线
│ CLK ├─────────>│ GPIO 18 │  ← 黄线
│ CS  ├─────────>│ GPIO 5  │  ← 绿线
│ DC  ├─────────>│ GPIO 17 │  ← 橙线
│ RST ├─────────>│ GPIO 16 │  ← 白线
│BUSY ├─────────>│ GPIO 4  │  ← 灰线
└─────┘          └─────────┘
```

---

#### 3. 注意事项（常见坑）

**⚠️ 电源电压：**
- 墨水屏必须使用 **3.3V**，接 5V 会烧毁！
- ESP32 开发板的 3V3 引脚输出能力通常为 500-700 mA，足够驱动单个墨水屏
- 如果同时连接多个外设，考虑使用外部 3.3V 稳压模块（AMS1117-3.3）

**⚠️ SPI 引脚冲突：**
- ESP32 有两组 SPI（HSPI 和 VSPI），默认库使用 VSPI
- 如果项目中有 SD 卡或其他 SPI 设备，需确认引脚不冲突
- 可在代码中自定义引脚（GxEPD2 支持）

**⚠️ 墨水屏供电时序：**
- 墨水屏初始化时会有较大瞬时电流（30-50 mA）
- 不要在刷新过程中断电，可能导致屏幕残留
- 使用电池供电时，确保电池输出能力足够（不能用纽扣电池）

**⚠️ 长时间刷新问题：**
- 墨水屏不应持续刷新超过 1 分钟（会发热）
- 更新完成后应调用 `display.hibernate()` 进入低功耗
- 不要在 `loop()` 中无限循环调用 `display.update()`

### 代码配置示例

```cpp
#include <GxEPD2_BW.h>
#include <GxEPD2_420.h>  // 4.2" 屏幕驱动

// 引脚定义（与接线对应）
#define EPD_CS    5
#define EPD_DC    17
#define EPD_RST   16
#define EPD_BUSY  4

// 创建显示对象（VSPI，默认 MOSI=23, SCK=18）
GxEPD2_BW<GxEPD2_420, GxEPD2_420::HEIGHT> display(
    GxEPD2_420(EPD_CS, EPD_DC, EPD_RST, EPD_BUSY)
);

void setup() {
    Serial.begin(115200);
    
    // 初始化显示
    display.init(115200);  // 串口调试波特率
    display.setRotation(0);  // 0/1/2/3 旋转方向
    display.setTextColor(GxEPD_BLACK);
    
    // 测试全刷
    display.setFullWindow();
    display.firstPage();
    do {
        display.fillScreen(GxEPD_WHITE);
        display.setCursor(10, 50);
        display.print("Hello BusArrival!");
    } while (display.nextPage());
    
    // 进入休眠模式（降低功耗）
    display.hibernate();
}
```

## 常见问题

### Q1：墨水屏显示模糊或有条纹？
**原因：** SPI 时钟过快、杜邦线过长、电源纹波
**解决：**
- 降低 SPI 速度（`display.init(115200)` 改为 `57600`）
- 杜邦线长度 < 20cm
- 在 VCC-GND 间并联 100μF 电容

---

### Q2：Wi-Fi 连接后墨水屏花屏？
**原因：** Wi-Fi 与 SPI 共用 GPIO 导致冲突（ESP8266 常见问题，ESP32 较少）
**解决：**
- 在 Wi-Fi 连接完成后再初始化墨水屏
- 避免使用 GPIO 6-11（ESP32 内部 Flash 占用）

---

### Q3：Deep Sleep 唤醒后黑屏？
**原因：** 墨水屏需重新初始化，内容不会自动恢复
**解决：**
```cpp
void setup() {
    display.init();  // 每次唤醒重新初始化
    display.setFullWindow();
    // 重新绘制内容...
}
```

---

### Q4：续航远低于预期？
**排查步骤：**
1. 万用表测量 Deep Sleep 电流（应 < 1 mA）
2. 检查是否有外设未断电（LED 指示灯、稳压芯片）
3. 确认代码中调用了 `WiFi.mode(WIFI_OFF)`
4. 某些开发板稳压芯片静态电流较大（换用低功耗 LDO）
